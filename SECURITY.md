# Security Policy

The Sterling Design Token (STER) ecosystem prioritizes transparency, safety, and responsible disclosure.
This document explains how to report a security concern and what is in scope.

---

## 🔹 Reporting a Vulnerability

If you discover a security issue related to:

- Token metadata
- Repository documentation
- Transparency files
- Ecosystem websites or integrations
- On-chain interactions
- Wallet, pool, or lock references

please report it privately.

### **How to report:**

1. Email **info@sterlingdesignventures.us** with the subject line "STER security report"
2. Provide:
   - A clear description of the issue
   - Steps to reproduce (if applicable)
   - Any relevant links or screenshots

Do **not** publicly disclose a vulnerability before it has been reviewed.

---

## 🔹 In-Scope Issues

- Incorrect or misleading on-chain references
- Broken transparency links
- Metadata inconsistencies
- Documentation errors that could cause user confusion
- Security concerns related to ecosystem websites or integrations
- Any issue that could mislead token holders or users of an SDV property

---

## 🔹 Out-of-Scope Issues

- Personal wallet security (users are responsible for their own keys)
- Issues unrelated to STER or an SDV property
- Exchange-specific bugs
- Third-party platform outages
- Speculative or theoretical vulnerabilities without evidence

---

## 🔹 A Note on Impersonation

SDV will never ask for your seed phrase or private key, and will never ask you to send tokens to "verify" a wallet. Official links are listed in [README.md](README.md).

---

## 🔹 Responsible Disclosure

We appreciate responsible, good-faith reporting.
All valid reports will be reviewed promptly, and fixes will be documented in this repository.

Thank you for helping maintain the integrity and safety of the STER ecosystem.
